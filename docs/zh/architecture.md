# 架构

Templater 是一个可组合的项目脚手架系统，围绕一个简单理念构建：

> 模板不是文件夹的副本。  
> 它是版本化、类型化、可执行的工件。

Templater 由三个独立层级组成：
- 核心引擎
- CLI
- VS Code 扩展

系统以 CLI 为先。扩展是 UX 层 —— 而非引擎。

---

## 理念

Templater 围绕以下不可妥协的原则构建：

- **确定性生成** — 相同输入必须产生相同输出。
- **默认安全** — 除非明确允许，否则无破坏性行为。
- **关注点分离** — UI 层从不包含生成逻辑。
- **类型化配置** — 模板以代码定义，而非松散 JSON。
- **可移植性** — 模板必须可通过 Git 或 npm 共享。
- **最小魔法** — 显式优于隐式。

Templater 是基础设施。基础设施必须可预测。

---

## 高层架构

Templater 分为三个包：

### 1. `@templater/core`

引擎。

职责：
- 模板加载
- 配置验证
- 渲染
- 文件规划
- 写入策略
- 受控钩子执行
- 元数据生成

无 UI。无提示。无网络。

---

### 2. `templater` (CLI)

命令行界面。

职责：
- 用户提示
- 模板安装
- 缓存管理
- 执行编排
- 格式化输出

CLI 依赖 `@templater/core`。

---

### 3. `templater-extension`

VS Code 扩展。

职责：
- 命令面板集成
- QuickPick UI
- 进度通知
- 调用核心逻辑（直接或通过 CLI）

扩展不包含任何生成逻辑。

---

## Monorepo 结构

Templater 使用 pnpm workspace。

```
templater/
packages/
core/
cli/
extension/
examples/

```

这使：
- 共享类型集中
- 版本统一
- 开发一致

## 核心引擎设计

核心负责确定性生成。

### 生成流程

1. 加载模板目录
2. 解析并验证 `templater.config.ts`
3. 解析问题模式
4. 从调用方（CLI/扩展）接收答案
5. 构建模板上下文
6. 创建生成计划（内存中）
7. 应用文件系统策略
8. 执行生命周期钩子
9. 写入 `.templater/meta.json`

核心从不提问。  
它接收已解析的输入。

---

## 模板

模板是包含以下内容的目录：

- `templater.config.ts`
- 源文件目录（通常为 `files/`）

模板以代码定义以实现：
- 类型安全
- 钩子支持
- 未来可扩展性

它们必须保持：
- 自包含
- 导入时无副作用
- 可预测

---

## 渲染

Templater 使用渲染引擎（初始为 Handlebars）。

支持的功能：
- 变量
- 条件
- 简单辅助函数

二进制文件会被检测并无转换地复制。

渲染以确定性方式应用，从不修改源模板。

---

## 写入策略

Templater 从不静默覆盖。

支持的策略：
- `fail`
- `skip`
- `overwrite`
- `prompt`（由 UI 处理）

核心在写入前计算文件计划。

---

## 模板上下文

模板可定义生命周期钩子：

- `beforeGenerate`
- `afterGenerate`

钩子在受限的上下文 API 中执行。

上下文：
- 暴露已解析变量
- 允许受控写入
- 可选允许命令执行
- 防止不受控的文件系统访问

安全性与可重现性优先于灵活性。

---

## 项目元数据

生成的项目包含来源元数据：

```
.templater/meta.json
```

示例：

```json
{
  "template": "landing-basic",
  "version": "1.0.0",
  "generatedAt": "2026-02-28T12:00:00Z"
}
```

这支持：

* 未来更新机制
* 溯源追踪
* 调试

---

## 模板分发

Templater 支持多种分发模式：

### 本地模板

基于路径的生成。

### 基于 Git 的模板

本地安装并缓存。

### 基于 npm 的模板

版本化且可重现。

未来：托管注册表。

---

## 存储

Templater 使用本地用户目录：

* macOS/Linux: `~/.templater`
* Windows: `%USERPROFILE%\.templater`

结构：

```
templates/
cache/
config.json
```

存储由 CLI 管理。

---

## 错误处理

错误是：

* 类型化
* 显式
* 可操作

核心从不直接打印到 stdout。  
它返回结构化结果。

UI 层负责格式化输出。

---

## 测试策略

核心：

* 渲染与规划的单元测试
* 使用示例模板的集成测试
* 确定性输出的快照测试

CLI：

* 命令级烟雾测试
* 端到端生成测试

扩展通过集成场景进行测试。

---

## 版本策略

Templater 遵循语义化版本。

在 DSL 稳定之前：

* `0.x`

稳定后：

* `1.0.0`

破坏性变更会被记录。

## 设计总结

Templater 是：

* CLI 优先
* 强类型
* 设计精简

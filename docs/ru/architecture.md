# Архитектура

Templater — модульная система создания каркасов проектов, построенная на простой идее:

> Шаблон — это не копия папки.  
> Это версионный, типизированный исполняемый артефакт.

Templater состоит из трёх независимых слоёв:
- ядро (core engine),
- CLI,
- расширение для VS Code.

Система CLI-first. Расширение — слой UX, а не движок.

---

## Философия

Templater построен на нескольких незыблемых принципах:

- **Детерминированная генерация** — одинаковые входные данные должны давать одинаковый результат.
- **Безопасность по умолчанию** — никаких разрушительных действий без явного разрешения.
- **Разделение ответственности** — слои UI не содержат логику генерации.
- **Типизированная конфигурация** — шаблоны определяются кодом, а не сырым JSON.
- **Портативность** — шаблоны должны распространяться через Git или npm.
- **Минимум магии** — явное важнее неявного.

Templater — инфраструктура. Инфраструктура должна быть предсказуемой.

---

## Высокоуровневая архитектура

Templater разделён на три пакета:

### 1. `@templater/core`

Движок.

Ответственность:
- загрузка шаблонов
- валидация конфигурации
- рендеринг
- планирование файлов
- политики записи
- контролируемое выполнение хуков
- генерация метаданных

Без UI. Без промптов. Без сетевых вызовов.

---

### 2. `templater` (CLI)

Интерфейс командной строки.

Ответственность:
- вопросы пользователю
- установка шаблонов
- управление кэшем
- оркестрация выполнения
- форматированный вывод

CLI зависит от `@templater/core`.

---

### 3. `templater-extension`

Расширение для VS Code.

Ответственность:
- интеграция с палитрой команд
- QuickPick UI
- уведомления о прогрессе
- вызов логики ядра (напрямую или через CLI)

Расширение не содержит логики генерации.

---

## Структура монорепозитория

Templater использует pnpm workspace.

```
templater/
packages/
core/
cli/
extension/
examples/
docs/
.github/
```

Это обеспечивает:
- централизацию общих типов
- единое версионирование
- согласованную разработку

## Дизайн ядра

Ядро отвечает за детерминированную генерацию.

### Поток генерации

1. Загрузка директории шаблона
2. Парсинг и валидация `templater.config.ts`
3. Разрешение схемы вопросов
4. Получение ответов от вызывающей стороны (CLI/расширение)
5. Построение контекста шаблона
6. Создание плана генерации (в памяти)
7. Применение политики к файловой системе
8. Выполнение хуков жизненного цикла
9. Запись `.templater/meta.json`

Ядро никогда не задаёт вопросов.  
Оно получает готовые входные данные.

---

## Шаблоны

Шаблон — директория, содержащая:

- `templater.config.ts`
- директорию с исходными файлами (обычно `files/`)

Шаблоны определяются кодом для:
- типобезопасности
- поддержки хуков
- будущей расширяемости

Они должны оставаться:
- самодостаточными
- без побочных эффектов при импорте
- предсказуемыми

---

## Рендеринг

Templater использует движок рендеринга (сначала Handlebars).

Поддерживаемые возможности:
- переменные
- условия
- простые хелперы

Бинарные файлы определяются и копируются без трансформации.

Рендеринг применяется детерминированно и никогда не изменяет исходные шаблоны.

---

## Политики записи

Templater никогда не перезаписывает файлы молча.

Поддерживаемые политики:
- `fail`
- `skip`
- `overwrite`
- `prompt` (обрабатывается UI)

Ядро вычисляет план файлов перед записью.

---

## Контекст шаблона

Шаблоны могут определять хуки жизненного цикла:

- `beforeGenerate`
- `afterGenerate`

Хуки выполняются в рамках ограниченного API контекста.

Контекст:
- предоставляет разрешённые переменные
- позволяет контролируемую запись
- опционально разрешает выполнение команд
- предотвращает неконтролируемый доступ к файловой системе

Безопасность и воспроизводимость приоритетнее гибкости.

---

## Метаданные проекта

Сгенерированные проекты содержат метаданные происхождения:

```
.templater/meta.json
```

Пример:

```json
{
  "template": "landing-basic",
  "version": "1.0.0",
  "generatedAt": "2026-02-28T12:00:00Z"
}
```

Это позволяет:
- будущие механизмы обновления
- отслеживание происхождения
- отладку

## Распространение шаблонов

Templater поддерживает несколько моделей распространения:

### Локальные шаблоны

Генерация по пути.

### Git-шаблоны

Установка и кэширование локально.

### npm-шаблоны

Версионирование и воспроизводимость.

В перспективе: хостируемый реестр.

---

## Хранилище

Templater использует локальную пользовательскую директорию:

* macOS/Linux: `~/.templater`
* Windows: `%USERPROFILE%\.templater`

Структура:

```
templates/
cache/
config.json
```

Хранилищем управляет CLI.

---

## Обработка ошибок

Ошибки:
- типизированы
- явны
- actionable

Ядро никогда не выводит напрямую в stdout.  
Возвращает структурированные результаты.

Форматированием вывода занимаются слои UI.

---

## Стратегия тестирования

Ядро:
- unit-тесты рендеринга и планирования
- интеграционные тесты с примерами шаблонов
- snapshot-тестирование детерминированного вывода

CLI:
- smoke-тесты на уровне команд
- end-to-end тесты генерации

Расширение тестируется через интеграционные сценарии.

---

## Стратегия версионирования

Templater следует семантическому версионированию.

Пока DSL не стабилизирован:
- `0.x`

После стабилизации:
- `1.0.0`

Критические изменения документируются.
